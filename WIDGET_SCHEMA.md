# WIDGET SCHEMA & REGISTRY

**Project:** Milk-Reporting  
**Date:** August 17, 2026  

---

## 1. Widget System Overview

Milk-Reporting uses a flexible, modular Widget Registry.
Instead of hardcoding dozens of platform-specific widgets (e.g. `MetaReachWidget`, `GoogleROASWidget`), widgets are **generic data visualization drivers** configured via a standardized JSON schema.

A single `LineChartWidget` can render Meta Reach, Google Spend, TikTok Video Views, or Instagram Follower Growth by simply receiving a different `dataConfig`.

| **Table** | `table` | Multi-column row listing of campaigns, ads, or content |

| **Heatmap** | `heatmap` | Day-of-week / hour-of-day performance grid |
| **Timeline** | `timeline` | Chronological event & post performance timeline |
| **Text** | `text` | Markdown text annotation / client notes block |
| **Image / Logo**| `image_logo` | Brand asset or client logo widget |

## 4. Grid Snapping & Layout Engine Mechanics

The widget system relies on a 12-column responsive grid layout:

* **Grid Width (`w`):** Range 1 to 12.
  * KPI Cards default to `w: 3` (4 cards per row).
  * Charts default to `w: 6` (2 charts per row) or `w: 12` (full-width timeline).
  * Tables default to `w: 6` or `w: 12`.
* **Grid Height (`h`):** Expressed in grid rows (e.g. `h: 3` = ~180px height).
* **Grid Coordinates (`x`, `y`):** Column offset `x` (0-11) and vertical row `y`.
* **Snapping & Collision:** When dragging or resizing a widget in Edit Mode (LobsterBoard style), collision detection automatically pushes surrounding widgets down while snapping to integer grid coordinates.
* **Layout Persistence:** Editing actions (drag, resize, add, configure, delete) trigger debounced updates saving the grid layout to the `dashboard_widgets` table in Supabase.
